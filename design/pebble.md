# 하루 — 눈 달린 조약돌 생성 규칙

하루는 그림 파일이 아니라 **번호(seed) 하나 + 이 규칙**으로 그립니다. 같은 번호면 iOS · Android · 위젯 어디서나 같은 돌이 나와야 합니다.
시안: `pebble.html` 아티팩트 (브라우저 시안은 mulberry32, 앱은 아래 SplitMix64 사용).

## 1. 번호
- 처음 설치할 때 무작위 64비트 정수 하나를 만들어 저장합니다. 생년월일 등 개인정보와 무관합니다.
- 한 번 정해지면 바뀌지 않습니다. 기기를 바꿀 때 번호만 옮기면 같은 하루가 따라옵니다.
- 난수: 명언 순서와 같은 `SplitMix64(seed)`. `r()` = 다음 값의 상위 53비트 / 2^53 (0 ≤ r < 1).

## 2. 특징 뽑기 — 순서 고정
아래 순서를 절대 바꾸지 않습니다. 순서가 바뀌면 모든 사람의 하루가 바뀝니다. `lerp(a,b,r())`는 a~b 사이 값입니다.

| # | 특징 | 규칙 |
|---|---|---|
| 1 | 돌 종류 | 가중치 뽑기 (아래 표) |
| 2 | 바탕색 | 종류의 색 후보 중 하나 → 밝기 ±6% |
| 3 | 크기 | r<0.1 작은 돌 0.62–0.72 · r>0.9 큰 돌 1.00–1.08 · 그 외 0.76–0.94 |
| 4 | 납작함 | 세로/가로 0.60–0.92 |
| 5 | 기울기 | ±0.45 rad |
| 6 | 윤곽 물결 | k=2..6 각각 세기 `r()*0.07/(k-1)*1.6`, 위상 `r()*2π` |
| 7 | 바닥 평평함 | 0.10–0.30 (아래쪽 35%부터 눌림) |
| 8 | 눈 크기 | 돌 가로 대비 0.15–0.23 |
| 9 | 짝눈 | 9% → 작은 눈 비율 0.62–0.78 (아니면 0.92–1.00) |
| 10 | 한쪽에 몰린 눈 | 12% → 가로 ±0.22–0.32 (아니면 ±0.08) |
| 11 | 눈 높이 · 간격 · 기울기 | −0.22–0.02 · 0.90–1.35 · ±0.175 rad |
| 12 | 엉뚱한 시선 | 6% → 두 눈동자가 서로 다른 곳을 봄 |
| 13 | 기본 시선 | x ±0.6, y ±0.4 |
| 14 | 눈동자 크기 | 흰자 대비 0.50–0.64 |
| 15 | 무늬 번호 | 32비트 정수 (무늬 전용 난수의 시작값) |

## 4. 그리기 순서
1. 바닥 그림자 (흐린 타원)
2. 몸: 타원 × (1 + Σ물결) 180점 → 바닥 눌림 → 기울기 → 이웃 점 중간을 잇는 2차 곡선
3. 몸 안쪽만 (clip): 흐린 얼룩 14개 → 무늬 → 왼쪽 위 빛 · 오른쪽 아래 그늘 → 가장자리 어둡게 → 광택 0.3 초과면 반사광
4. 눈: 흰 플라스틱 눈알(안쪽 그림자 · 테두리) → 검은 눈동자(흰자 안에서만 움직임) → 작은 반사점
5. 무늬 · 얼룩은 15번 무늬 번호로 만든 별도 난수를 씁니다. 화면 크기와 무관하게 같은 모양이 되도록 모든 길이는 캔버스 폭 비율로 계산합니다.

## 5. 움직임
- 눈동자만 움직입니다. 몸은 그대로입니다.
- iOS Core Motion · Android SensorManager로 기울기를 받아 눈동자가 굴러갑니다. 가끔 깜빡입니다.
- 시스템의 ‘동작 줄이기’가 켜져 있으면 눈동자는 기본 시선에 고정하고 깜빡임만 둡니다.
- 위젯은 움직일 수 없으므로 한 장으로 그려 넣습니다 (iOS ImageRenderer, Android Bitmap).

## 6. 검증
- 두 플랫폼 테스트에 같은 seed 목록 → 같은 특징 값(종류 · 크기 · 눈 위치 등)을 확인하는 예시를 둡니다.
- 무늬 이미지는 픽셀 단위로 같을 필요는 없습니다. 특징 값이 같으면 됩니다.
